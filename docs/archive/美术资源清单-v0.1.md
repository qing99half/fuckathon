# 《预制黑客松模拟器》美术资源清单 v0.1

> 目的：比赛场景和小人由玩家选择驱动（场地决定地图、Title 决定人数、后勤决定设施、
> 赞助决定展位横幅），**全部资源必须在开发前设计并生产完毕**，运行时只做组合，不做现场生成。
>
> **生产工具：一律使用已配置好的 `image_generation` Skill 生成原始像素资源**，
> 生成后走统一后处理管线（见第 6 节）。UI 全面禁用 emoji，图标全部像素化。

## 3. C+D 组：角色 sprite

### 3.1 选手小人（核心，数量由 Title 声量驱动 15/25/40 个实例）
- 基础体型：8×8 → 图集按 16×16 帧格制作（留出动作余量）
- 4 状态 × 2 帧动画：敲代码（头+手微动）/ 趴桌 / 走路 / 排队站立
- 换色方案：**同一 sprite × 8 套调色板**（发色 4 × 衣色 4 取 8 组合），运行时用 Canvas 像素级换色，**不需要 8 份图**
- 共 1 张基础图集（4 状态×2 帧 = 8 帧）+ 调色板配置 JSON

### 3.2 特殊 NPC（各 1 张小图集）
1. **领导**：西装、致辞手势 2 帧、舞台专用
2. **摄影师**：举相机、闪光灯特效帧（出现时全屏微闪）
3. **赞助商代表**：胸前挂绳牌，展位旁罚站
4. **志愿者**：红马甲，走动搬运
5. **外卖小哥**：凌晨泡面门事件专用，园区门口迷路循环走

## 5. 字体（最大单项，必须子集化）

| 字体 | 用途 | 体积控制 |
|---|---|---|
| Fusion Pixel | 标题/大数字/窗口栏 | **子集化**：只保留游戏文案实际用到的字符（约 1500-2000 字），woff2 ≈ 400-600 KB |
| Press Start 2P | HUD 数字/英文 | 原字体极小，直接用，~15 KB |
| 思源宋体 Bold | 红头文件/结局卡 | 子集化 ≈ 200 KB；**降级：系统宋体** |

子集化工具：fonttools `pyftsubset`，字符表从全部 JSON 文案自动提取（构建脚本做）。

## 6. 生产管线（Skill 使用规范）

1. **生成**：使用已配置的 `image_generation` Skill，按本清单逐组生成。
   prompt 模板：`pixel art, {描述}, 8-bit retro game style, limited 16-color palette, transparent background, crisp pixels, no anti-aliasing`
2. **后处理**（Python 脚本，开发时做一次）：
   - 调色板归一：映射到美术方案 §2.3 的 16 色
   - 尺寸校验：tile 16×16 / 图标 16×16 / 横幅 48×24 / 插画 640×480
   - 转 PNG-8 压缩 + 合并图集（减少 HTTP 请求数）
3. **验收标准**：与 16 色调色板一致；无渐变无抗锯齿；透明底干净；小人两帧动画动起来不"抽搐"
4. 产出目录：`public/assets/{tiles,sprites,npc,banners,icons,endings,ui}/`

## 7. 性能硬指标（owner 决定：开发时严禁使用降级手段）

**不设运行时降级方案。** 性能靠资源纪律一次性做对：

| 指标 | 硬上限 |
|---|---|
| 首屏资源（图片+图集） | < 700 KB |
| 字体（子集化 woff2 合计） | < 800 KB |
| 音频 | 懒加载，不进首屏；首次交互后启动（浏览器策略合规） |
| 同屏 sprite 数 | ≤ 60（小人按 Title 声量 15/25/40 + NPC） |
| 同屏弹幕 | ≤ 12 条，对象池复用 DOM 节点 |
| Canvas 帧率 | 稳定 30fps 即达标 |

**达标的手段只有这些**：图集合并、PNG-8、字体子集化、音频懒加载、加载页一次性预载、
Canvas 关闭抗锯齿、对象池。做不到就砍资源数量（如小人调色板 8→4），**不做双套实现、不做静态图兜底**。
